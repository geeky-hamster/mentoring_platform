## Source of truth

```
src/schema.py  ──generates──▶  database/schema.sql  ──describes──▶  these docs
                                      │
                                      ├── database/tests/integrity.sql
                                      ├── seed data (backend/app/cli.py)
                                      └── ERD / DFD / chart SQL
```

- **Never hand-edit `database/schema.sql`.** It is generated by `src/schema.py` (see the repo `AGENTS.md`).
- These documents are handwritten because they add meaning the DDL cannot express: lifecycle prose, flow IDs, metric definitions, chart queries.
- When a column, constraint or enum changes, update **all three** companions in the same PR.

## Validate the SQL

All chart queries are executable. Against a seeded database:

```bash
# 1. Apply the schema to a scratch database
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f database/schema.sql

# 2. Load demo data (from backend/)
python -m app.cli seed-demo

# 3. Run any chart query directly
psql "$DATABASE_URL" -c "SELECT role, count(*) FROM users GROUP BY role;"
```

To re-verify every query in `CHARTS.md` at once, extract the fenced `sql` blocks and run them sequentially; each block is self-contained and read-only.

Expected sanity values on a fresh seed: 10 users (1 admin, 3 students, 6 mentors), 6 mentor profiles (5 approved, 1 pending), 3 requests, 2 active mentorships, 1 completed session, 2 feedback rows, 20 slots. The live Neon dataset has since accumulated manual-test rows (11 users, 4 accepted + 1 pending requests, 4 active mentorships, 1 completed + 1 cancelled session, 7 notifications) — see `CHARTS.md` §6.

## Reading order for a new team member

1. `DATABASE-SPEC.md` §2 (domain) and §5 (join map) — the two things that cause the most bugs.
2. `DFD.md` §2–§3 — the system in one page.
3. `DATABASE-SPEC.md` §8 — the states you will implement in the UI.
4. `CHARTS.md` §2 — the vocabulary used in every dashboard conversation.
5. `DFD.md` §5–§6 — only if you are touching requests or scheduling.

## Maintenance checklist

- [ ] `schema.sql` regenerated, not edited
- [ ] New column has a description and an example in §4
- [ ] New enum value appears in §7 and in any chart filter
- [ ] New invariant added to §9 and, if enforceable, to `database/tests/integrity.sql`
- [ ] New flow added to `DFD.md` §7 with a unique ID and the CRUD matrix updated
- [ ] New chart has an ID, a question, a type, and runnable SQL
- [ ] Demo expectations in `CHARTS.md` §6 still true after seeding
- [ ] "Last verified" date updated in all three documents
